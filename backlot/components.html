Icons

Single-color SVG only. Each lives as a <symbol> in the sprite and paints with currentColor. Reference with <svg class="bl-icon"><use href="#icon-NAME"/></svg>. Icon-only buttons need an aria-label.

Sizes: default 20px (.bl-icon), .bl-icon--sm 16px, .bl-icon--lg 28px.

Buttons

Danger is a solid red for prominent, standalone destructive actions (bulk delete, hard confirmations). Destructive is an outline-red variant for a Delete that sits next to a primary Edit/Save — it stays clearly destructive without competing for visual weight.

Row utilities

.bl-row is a flex container with an 8px gap. Add --end to right-align (e.g. form footers) or --end-gapped for right-aligned with a 12px top margin. Use these instead of style="justify-content:flex-end" — the CSP blocks inline styles.

Client-side pager for in-memory lists (25/page by default; 50 and 100 available via the selector, persisted per list to localStorage). Create with BL_PAGINATE.create({ mount, render }) and feed rows via pager.setItems(rows); the pager hides itself for lists ≤25 rows. Sortable headers get data-sort-key="…" in the markup and are wired with BL_SORT.attach({ thead, columns, onChange }) — third click clears the sort. Sort state persists via storageKey.

Chip filter

Small pill group for single-select filtering. Consumer toggles .is-active on click and re-renders the filtered list — see onChipClick in comms.js for the canonical wiring.

Pair with .bl-search--sm inside .bl-comms-filters when the list also needs freeform search — the two share the same row.

Bulk action bar

Sticky toolbar that appears when any rows are selected. Left side owns the select-all + count; right side lists eligible actions with a (count) badge each, disabled when zero apply. See users.js for the selection state model and sequential runner.

Search field

Full-height search input for section toolbars. Focus lives on the wrapper — the inner input strips its own ring so the icon + input read as one control. Use .bl-search--sm when it shares a row with a chip filter.

Columns menu (popover)

Anchored to a trigger button, single-column list of checkable rows. Toggle visibility with the hidden attribute; close on outside-click and Escape.

Modal

Centered overlay for edit forms and confirmation. Toggle .is-open on the root; use role="dialog" + aria-modal="true" + aria-label, and wire Escape to close. Preview below is inlined (no overlay backdrop) so it stays visible on the guide page.

Edit user

3 / 12

Two footer patterns: Cancel + Save right-aligned (default .bl-modal-actions) for edit forms, and Delete + Edit centered for detail overlays (add .bl-modal-actions--center). The centered pattern pairs --destructive with --primary so Delete reads as destructive but subordinate. Note: the app's CSP blocks inline style="...", so use the modifier class — not style="justify-content:center".

Add .bl-modal-card--wide for detail overlays that render tables, timelines, or side-by-side facts (see #blRecDetail). It widens the card past the default read-column width.

Global search (topbar)

VIN / serial lookup that lives in the topbar on every section. Debounced ilike against records.serial_id, then deduped by VIN client-side — one row per unique vehicle with its latest status. Selecting a result opens the vehicle-history modal via BL_RECORDS.openVinHistory(serial), which lists every event for that VIN and lets managers drill into any single record.

Empty and error states reuse the same .bl-search-empty row inside the dropdown:

Searching…
No records match 4T1XZ.

Keyboard: ⌘K / Ctrl+K focuses the input, ↑ / ↓ walk results, Enter opens, Escape clears. Wired by search.js; the fetch pulls up to 50 rows ordered ts DESC and dedupes client-side keeping the first row per serial_id, capped at 8 unique VINs.

Damage + tire panels

Read-only panels inside the record-detail modal, ported from the driver app's inspection UI (damage.js). Backlot re-implements them under the bl-vin-* namespace to keep the app self-contained. Both are wrapped by renderDamagePanel(r) / renderTirePanel(r) in records.js — each returns an empty string when the record has no marks / no tire data, so quiet records stay quiet.

Vehicle history page

Full-page section #section-vin — not a modal. Shown programmatically via BL_NAV.show("vin") from either the global topbar search or a Records-table row click. Page head has a Back button that pops the previous section (BL_NAV.back()); no nav-bar tab, so the section is only reachable when you land on it. Body reuses the .bl-vin-header from the record-detail page (VIN + vehicle + latest status + summary meters). If the vehicle has body damage on file anywhere in its history, a Body damage panel renders below the header (marks unioned across all records, deduped by panel_id + damage_type, using the newest x/y for each). If any record logged tire issues, a Tires panel renders below that (latest full snapshot wins). Then the .bl-vin-timeline of every event. Each timeline row is a <details> — click drills into a per-record expanded panel with an Open full record button that opens the single-record detail modal for edit/delete.

Don't

  • Hardcode a #hex, pixel, or font-size when a token exists.
  • Use emoji or multi-color icons — single-color SVG <symbol> only.
  • Write a second escaper / formatter / toast — use BL_ESC, BL_FORMAT, BL_TOAST.
  • Reference any driver-app file (../app.css, DT_*). Backlot is self-contained.
  • Ship an icon-only control without an aria-label.
